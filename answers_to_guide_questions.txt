1. What is a StatelessWidget, and why is it appropriate for this application?
A StatelessWidget is a Flutter widget that does not manage mutable internal state and whose visual configuration does not change dynamically during runtime. It is appropriate for this application because all student profile details—including the name, student number, course, bio, and hobbies—are static, predefined values that do not require state changes or dynamic user-driven updates.

2. What does the build() method return?
The build() method returns a Widget (or widget subtree) that describes the user interface representation of the widget for the given BuildContext. The Flutter framework calls this method to construct and render the visual layout hierarchy on the device screen.

3. What is the difference between MaterialApp and Scaffold?
MaterialApp is the top-level root widget that defines overall application settings such as global themes, routing navigation, and Material Design configurations. On the other hand, Scaffold is a screen-level layout structure that implements the basic Material visual layout, offering dedicated slots for an AppBar, body content, FloatingActionButton, and drawer.

4. How do Column, Padding, and SizedBox help organize your screen?
Column arranges its child widgets vertically along the screen's main axis in a neat top-to-bottom sequence. Padding adds empty space around widgets to ensure content does not press against screen edges, while SizedBox creates precise, fixed spacing between adjacent widgets for clean visual separation.

5. Why did you use SingleChildScrollView in the profile page?
SingleChildScrollView was used to allow the profile screen content to scroll vertically whenever the total height of the widgets exceeds the available display height. This guarantees that all sections remain accessible across various screen resolutions and device orientations while preventing RenderFlex overflow errors.
